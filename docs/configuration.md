# 配置与重试说明

[返回 README](../README.md) · [代理与上游安全验证](network.md)

## 配置方式

在控制台「设置」修改参数，保存后对后续请求生效。设置存于数据库，重启后仍覆盖同名文件配置。

直接运行程序时，可将 [config.example.json](../config.example.json) 复制为 `--root` 指定目录下的 `config.json` 后修改。Docker 默认只挂载数据目录；如需使用配置文件，须另行将它挂载到 `/app/config.json`。监听地址和端口修改后需要重启服务。

## 版本更新

在「设置 → 版本更新」检查 `do-whilefor/zcode2api` 的最新正式 Release，查看版本和发布说明。同一发行版本上的本地热修复不会被正式包覆盖，仅提供更高版本的更新。

一键更新支持由 root 运行、以当前程序为主进程的 Linux/systemd 服务。更新沿用已保存的出站代理，校验发行包 SHA256，并将当前程序、数据库快照及配置备份到 `data/updates/job-*`。只替换可执行文件，保留账号、配置和其他数据；新程序启动失败时自动恢复旧程序。重启可能中断正在进行的请求，完成后需重新登录。

Docker 需在宿主机更新镜像并重建容器，其他部署方式使用页面提供的发行包入口。Node.js、jsdom、Mihomo 等可选依赖不会随程序更新而自动升级。

## 配置项

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `web_port` / `gateway_port` | `6789` / `6780` | 控制台与推理网关端口 |
| `host` | `127.0.0.1` | 本机直接运行时的监听地址 |
| `poll_interval_sec` | `60` | 账号余额轮询基础间隔，秒 |
| `poll_jitter_sec` / `poll_concurrency` | `10` / `4` | 轮询抖动秒数与并发数 |
| `daily_claim_time` | `19:02` | 每日自动领取免费卡的时间，北京时间 `HH:MM`；同一天已执行过则不重复领取 |
| `conversation_affinity_minutes` | `10` | 客户端提供会话标识时的账号亲和时间，分钟 |
| `default_reasoning_level` | `low` | 客户端与密钥均未指定时的默认思考强度，可选 `low` / `high` / `max` |
| `retry.rate_limit_retry_interval_ms` | `1000` | 上游未指定等待时间时，账号共享的并发暂忙冷却间隔；同时用于普通限流重试 |
| `retry.busy_wait_sec` | `60` | 本地账号槽位全部占用时，等待空闲账号的时长，秒 |
| `retry.max_attempts` / `retry.total_budget_ms` | `10` / `120000` | 普通故障的尝试次数 / 常规排队与重试预算（毫秒） |
| `http.first_token_timeout_ms` | `60000` | 上游首个有效内容超时，毫秒 |
| `http.idle_timeout_ms` | `120000` | 上游流空闲超时，毫秒 |
| `http.total_timeout_ms` | `0` | 整轮推理超时；`0` 表示不设整轮时限 |
| `app_version` | `3.17.2` | 额度、领卡等管理 API 的版本标识；上游活动可能按版本筛选 |
| `http.client_version` | `0.17.0` | 推理 API 的版本标识 |

代理、订阅和验证码的字段、依赖与限制见[网络配置文档](network.md)。

## 默认思考强度

可选 `low`、`high`、`max`。优先级：**客户端 → 密钥 → 全局设置**。

`low` 仍开启思考。客户端发送 `thinking.type=disabled` 时保留该设置；若模型返回 1210，请在客户端开启思考或移除关闭参数。

## 环境变量

| 环境变量 | 用途 |
| --- | --- |
| `ZCODE2API_DATA_DIR` | 指定数据目录 |
| `ZCODE2API_HOST` | 指定监听地址；Docker 镜像内默认为 `0.0.0.0` |
| `ZCODE2API_WEB_PORT` / `ZCODE2API_GATEWAY_PORT` | 指定控制台与网关端口 |
| `ZCODE2API_ADMIN_PASSWORD` | 指定管理密码；设置后使用该值登录 |
| `TZ` | 容器时区，Compose 默认 `Asia/Shanghai` |

## 调度与重试

单账号最多同时处理 3 个推理请求，所有模型共享名额；本地名额全部占用时，换号或按 `retry.busy_wait_sec` 排队。

| 情况 | 网关行为 |
| --- | --- |
| 明确的账号并发暂忙（3008/3009/3010） | 所有请求共享该账号的暂忙状态，优先换其他可用账号；优先遵守 `Retry-After`，缺失时默认冷却 1 秒 |
| 可用账号全部并发暂忙 | 进入统一队列，持续等待至恢复或取消；冷却结束后每账号仅放行一个恢复探测，开始有效输出后恢复正常名额 |
| 普通限流或过载（429、过载业务码、HTTP 503/529） | 先尝试其他账号，本次可用账号都受限后开启 **10 秒重试窗口**；不判定为代理节点故障 |
| 额度耗尽或凭据失效 | 从本次请求中排除该账号并换号，同时更新余额或授权状态 |
| 已经输出正文、思考或工具调用 | 停止整轮重放，避免重复回答或重复执行工具 |
| 参数错误 | 返回对应错误 |
| 明确的出口拦截或代理连接故障 | 出口被 WAF 拦截单独暂避 60 秒；有代理连接或认证故障证据时隔离 30 秒。尚未输出时可在次数与时间预算内切换节点，随后请求可在隔离到期后重新尝试 |
| 验证票据失效、需要人工验证或 SDK 环境错误 | 票据失效在同一出口重新验证一次；其他情况返回具体错误，不剔除代理节点 |

上游并发暂忙不消耗普通重试次数和预算；普通限流窗口到期后返回错误。队列最多容纳 1024 个请求，按匹配账号与等待顺序调度，取消后立即移出。网络和普通服务端故障使用退避重试，正常生成中的回复不受重试预算截断。

## 日志保存与筛选

调用记录、调度时间线和审计写入数据目录的 SQLite 数据库，不按时间或条数自动清理，重启后保留。容器部署需保留挂载的数据目录。

各日志分区独立筛选和分页，每页 20 条，支持时间范围与指定页跳转。页面链接保留查询条件；新增记录在点击刷新后显示。

调用记录可按状态、错误、模型、账号、密钥和关键词搜索；调度可按结果、策略和候选账号搜索；审计可按操作者、动作和来源 IP 搜索。原始报错、请求 ID 和追踪 ID 保留在详情中。

## 领卡行为

领卡页仅展示每日 19:00（北京时间）开放的免费 Token 卡，从上游活动投放中识别 `ZCODE GLOBAL BUILD`，使用当次返回的 `plan_id` 手动领取。不展示其他活动奖励、待生效额度或领取记录。已移除定时自动领卡，旧配置中的 `claim_auto_enabled`、`claim_auto_min` 不再生效。

手动点击领取后，先提交领取请求；上游明确要求验证时自动运行服务器 SDK，在同一出口取新票据重试一次。需要人工交互或 SDK 环境不可用时转浏览器官方组件。网络中断不自动重发领取请求，需先刷新确认领取状态。账号风控、代理故障与验证码错误分别返回，不会把所有失败都当成需要人工验证。

- 网页领取使用阿里云官方组件，初始化后等待 2.1 秒自动验证。批量领取逐张验证，关闭或取消弹窗即停止当前流程。
- 票据不跨请求或账号复用，不保存到浏览器存储或日志。

网页 Cookie 导入仅用于受支持的平台资料等接口，**不能用于推理或余额查询**。推理和领卡需要账号具备有效的 ZCode 凭据。

## 数据目录

管理密码、数据库与端口文件均位于数据目录，默认为 `data`。Windows 启停脚本中的相对 `ZCODE2API_DATA_DIR` 以项目或解压目录为基准。

备份应整体保留数据目录，包括数据库、`secret.key` 和必要的 Cookie 文件，并限制备份访问权限。详见[安全说明](../SECURITY.md)。
