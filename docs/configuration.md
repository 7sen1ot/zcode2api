# 配置与重试说明

[返回 README](../README.md) · [代理与安全验证](network.md) · [协议兼容](protocol-compatibility.md)

## 服务入口

同一个 Go 进程启动 Web 控制台和推理网关，默认端口分别为 `6789` 和 `6780`。控制台管理账号、分组、API 密钥、领卡、调用记录及设置。推理网关接收 OpenAI 和 Anthropic 请求，按账号可用状态和分组策略调度，并向 ZCode 发起推理。账号、密钥、调用记录和 Web 设置保存在数据目录的 SQLite 数据库 `zcode2api.db` 中，网页资源随程序一同嵌入。[启动入口](../main.go) · [监听与生命周期](../internal/server/app.go)

两个端口都提供 `GET /healthz` 和 `GET /readyz`。`/healthz` 用于确认 HTTP 服务可响应。`/readyz` 统计数据库中状态为 `active` 的账号，至少一个时返回 200，否则返回 503。就绪状态不检查这些账号的余额、模型权限或上游连通性。[健康检查](../internal/server/app.go)

## 配置方式

Web 中保存的可编辑设置写入数据库，对后续请求生效，重启后继续覆盖配置文件中的同名选项。自动领卡开关和时间在「领卡中心」修改。网关固定使用 HTTP 推理，`inference_driver` 是接口中的兼容状态字段，旧配置文件中的同名字段可移除。

程序启动时读取 `--root` 目录下的 `config.json`，缺省配置使用内置默认值。非空的监听地址、端口和管理密码环境变量覆盖文件中的同名值。直接编辑配置文件后需重启。仓库的 Compose 默认只挂载数据目录，使用配置文件时可另行挂载到 `/app/config.json`。镜像已设置监听地址及两个端口的环境变量，更改容器监听值时需要同步调整这些变量和端口映射。[配置示例](../config.example.json) · [加载顺序](../internal/server/config/config.go) · [镜像默认值](../Dockerfile)

## 版本更新

### 网关程序

在「设置 → 版本更新」点击「检查更新」。发行包和官方容器镜像按 GitHub 最新正式发行版的版本号比较，源码构建按提交检查。

| 部署方式 | 更新方式 |
| --- | --- |
| 预编译发行包 | 有更高版本的当前平台发行包且部署支持在线安装时，可在 Web 更新并重启。Windows 用户进程、Linux 或 macOS 独立进程需要程序目录可写。Linux 的 systemd 系统服务还要求以 root 运行，网关为服务主进程，且可使用 `systemctl` 和 `systemd-run`。 |
| 从 Git 克隆编译 | 检查当前分支跟踪的远端提交，使用服务进程的 Git 网络配置。发现新提交后，手动更新源码，重新编译并重启。 |
| 从源码 ZIP 编译 | 查看 GitHub 默认分支的最新提交。缺少本地提交信息时需自行核对源码来源，手动下载、编译并重启。 |
| Docker Compose（官方 GHCR 镜像） | 同时使用 `compose.yaml` 和 `compose.update.yaml`，在宿主机部署目录运行 `zcode2api --docker-updater`。Web 提交更新后，由宿主机拉取对应版本的镜像并重建容器。 |
| Docker Compose（自行构建镜像） | 查看 GitHub 默认分支的最新提交。在宿主机核对并更新源码，重新构建镜像和容器。 |

发行包按 GitHub 官方摘要或官方 `SHA256SUMS` 校验。检查发行版和下载发行包可使用 Web 中配置的 GitHub 镜像与出站代理。[官方发行页](https://github.com/7sen1ot/zcode2api/releases)

Web 在线更新前，网关将数据库快照和已有的 `config.json` 备份到数据目录的 `updates/job-*`。本机更新还会备份原程序，容器更新保留原镜像用于回滚。重启可能中断进行中的请求，启动或健康检查失败时更新器会尝试回滚。Node.js、jsdom、Mihomo 等可选依赖需单独维护。

### ZCode 接口版本

当前代码将上游客户端版本固定为 **3.19.1**，用于推理请求、余额查询和领卡预览。「设置 → 网关与模型」显示该只读版本。旧的 `zcode_version_auto_update`、`zcode_version_check_interval_sec`、`app_version` 和 `http.client_version` 配置已退出使用。[版本定义](../internal/server/config/config.go)

## 配置项

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `web_port` / `gateway_port` | `6789` / `6780` | 控制台与推理网关端口 |
| `host` | `127.0.0.1` | 本机直接运行时的监听地址 |
| `bind_public` / `admin_bind_public` | `false` / `false` | 默认两个端口均绑定 `host`。启用 `bind_public` 会让网关绑定 `0.0.0.0`，同时启用 `admin_bind_public` 才会将控制台也切换到该地址 |
| `poll_interval_sec` | `30` | 账号余额轮询基础间隔，秒；限流和失败时延后检查；旧默认 5 秒仅迁移一次 |
| `poll_jitter_sec` / `poll_concurrency` | `0` / `3` | 轮询抖动秒数与并发数，并发可设为 1–3 |
| `daily_claim_enabled` | `true` | 是否启用每日定时领取；可在领卡中心开关 |
| `daily_claim_time` | `19:02` | 每日自动领取免费卡的时间，北京时间 `HH:MM`；按具体计划时刻记录执行及恢复状态 |
| `conversation_affinity_minutes` | `10` | 显式会话及 Responses 自动生成会话的账号亲和时间，单位为分钟，设为 `0` 关闭这两类绑定 |
| `default_reasoning_level` | `low` | 客户端与密钥均未指定时的默认思考强度，可选 `low` / `high` / `max` |
| `retry.rate_limit_retry_interval_ms` | `1000` | 上游未指定等待时间时，账号共享的并发暂忙冷却间隔；同时用于普通限流重试 |
| `retry.busy_wait_sec` | `60` | 本地账号槽位全部占用时，等待空闲账号的时长，秒 |
| `retry.max_attempts` / `retry.total_budget_ms` | `10` / `120000` | 普通故障的尝试次数 / 常规排队与重试预算（毫秒） |
| `http.first_token_timeout_ms` | `60000` | 上游首个有效内容超时，毫秒 |
| `http.idle_timeout_ms` | `120000` | 上游流空闲超时，毫秒 |
| `http.total_timeout_ms` | `0` | 单次上游推理超时，`0` 表示不设该时限 |
| `usage_log_retention_days` | `30` | 调用记录保留天数，最少 1 天 |
| `github_update_mirror` | 空字符串 | 检查和下载网关发行版时使用的 HTTPS 镜像基址 |
| `zcode_template_mode` | `main` | 请求模板，可选 `main` 或 `subagent`，见[模板与去重](protocol-compatibility.md#模板与去重) |

## 额度与页面刷新

服务端按 `poll_interval_sec` 轮询额度，实际间隔还受账号数量、请求耗时、并发、抖动和错误退避影响。相关参数在「设置 → 额度轮询」修改；关闭网页不停止服务端轮询。

Web 仪表盘和账号页在可见且未进行交互时约每 5 秒刷新。仪表盘从 SQLite 读取账号状态、已记录的余额和调用统计。账号页读取余额快照，平台显示名缓存未命中时可能查询上游资料。额度轮询由服务端独立调度。[日志刷新周期](#日志保存与筛选)

## 默认思考强度

可选 `low`、`high`、`max`，优先级为**客户端 → 密钥 → 全局设置**。

`low` 仍开启思考。客户端发送 `thinking.type=disabled` 时保留该设置；若模型返回 1210，请在客户端开启思考或移除关闭参数。

| 环境变量 | 用途 |
| --- | --- |
| `ZCODE2API_DATA_DIR` | 指定数据目录。直接运行程序时，相对路径以进程工作目录为基准。未设置时使用 `--root` 下的 `data/` |

## 调度与重试

单账号最多同时处理 3 个推理请求，所有模型共享名额；本地名额全部占用时，换号或按 `retry.busy_wait_sec` 排队。

| 情况 | 网关行为 |
| --- | --- |
| 明确的账号并发暂忙（3008/3009/3010） | 所有请求共享该账号的暂忙状态，优先换其他可用账号；默认基础冷却为 1 秒，恢复探测再次暂忙时延长等待，并遵守更长的 `Retry-After` |
| 可用账号全部并发暂忙 | 在总预算内排队等待恢复，客户端取消时退出。冷却结束后每个账号先放行一个恢复探测 |
| 普通限流或过载（429、过载业务码、HTTP 503/529） | 先尝试其他账号，本次可用账号都受限后开启最多 **10 秒**的重试窗口，受剩余总预算限制；不判定为代理节点故障 |
| 额度耗尽或凭据失效 | 从本次请求中排除该账号并换号，同时更新余额或授权状态 |
| 已经输出正文、思考或工具调用 | 停止整轮重放，避免重复回答或重复执行工具 |
| 参数错误 | 返回对应错误 |
| 明确的出口拦截或代理连接故障 | 全局代理池有可用备用节点且尚未输出时换节点重试；隔离时长和错误分类见[出口故障与切换](network.md#出口故障与切换) |
| 验证票据失效、需要人工验证或 SDK 环境错误 | 在原出口按[安全验证流程](network.md#安全验证)处理，返回具体验证错误，不据此剔除代理节点 |

上游并发暂忙不计入普通尝试次数，排队和重试仍受总预算约束。普通限流窗口到期后返回最近一次限流或过载错误。队列最多容纳 1024 个请求，按匹配账号与等待顺序调度，取消后立即移出。网络和普通服务端故障使用退避重试，正常生成中的回复不受重试预算截断。

网关对同一密钥的 `last_used_at` 最多每 30 秒写入一次。Token 配额用量独立记账。

## 日志保存与筛选

「日志」展示写入 SQLite 的推理调用记录，默认保留 30 天。服务启动、保留天数变更及此后每小时都会检查过期记录。缩短「设置 → 日志保留」中的天数会清理超过新期限的记录，删除后无法恢复。容器重建后需挂载原数据目录才能继续查看记录。

每页最多显示 20 条，超过 20 条时提供翻页和页码跳转。可按时间、状态、错误码、模型、账号或密钥筛选，也可搜索请求 ID 和追踪 ID。页面链接保留筛选条件和分页快照。

默认开启「实时」，第一页约每 3 秒检查最新日志 ID。ID 未变化时可跳过列表、筛选项和统计查询。没有新日志时约每 15 秒完整刷新，以反映保留期清理、账号或密钥改名，以及滚动时间范围的变化。点击「实时」可暂停，点击「刷新」可立即重新查询。网页切到后台、编辑筛选、查看详情、选中文字或翻到历史页时暂停自动刷新。刷新失败会保留当前内容，后续继续尝试。

管理员可通过 Web 端口的 `GET /api/performance` 查看最近调用的网关排队、重试、首个输出及生成等阶段的平均耗时、P50 和 P95。`limit` 默认为 100，最大为 1000，只取已记录阶段耗时的调用。这些耗时来自推理请求的调用日志。

常见错误码及处理方式见[故障排查](network.md#故障排查)。

## 领卡行为

领卡中心只识别上游活动投放中的 `ZCODE GLOBAL BUILD`、`ZCODE WEEKEND BUILD` 免费卡，使用当次返回的 `plan_id` 领取；卡片开放时间、额度和有效期以上游为准。

每日定时领取默认开启，时间为北京时间 19:02（固定使用 `Asia/Shanghai` 时区）。可在「领卡中心」开关自动领取、修改每日执行时间；保存后重排下一次执行，无需重启。对应配置为 `daily_claim_enabled` 和 `daily_claim_time`，旧的 `claim_auto_enabled`、`claim_auto_min` 不再生效。

定时任务需要服务及浏览器验证运行时可用。计划时刻后有 10 分钟恢复窗口，版本 2 的未完成检查点可在重启后恢复；已完成的同一计划时刻不重放，旧版已执行记录也不重放。修改时间会重排任务，同日较晚的新时刻可成为新任务。恢复前核对领取日志和已有卡片，每账号最多两次尝试；超过恢复窗口等待下一次计划，需人工处理的结果保留。执行前 3 分钟可预热浏览器，关闭开关或修改时间会取消当前准备及执行流程。

单张、批量和定时领取使用的验证方式及结果待确认时的处理见[领卡验证](network.md#领卡验证)。

网页 Cookie 导入仅用于受支持的平台资料等接口，**不能用于推理或余额查询**。推理和领卡需要账号具备有效的 ZCode 凭据。

## 数据目录

数据库为 `zcode2api.db`，实际监听端口和进程 ID 写在 `ports.json` 中。未通过配置文件或环境变量提供管理密码时，程序从 `admin-password.txt` 读取，首次启动且文件不存在时才生成。Windows 启停脚本中的相对 `ZCODE2API_DATA_DIR` 以项目或解压目录为基准。[安全说明](../SECURITY.md#账号与数据)
