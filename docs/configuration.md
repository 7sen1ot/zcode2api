# 配置与重试说明

[返回 README](../README.md) · [代理与安全验证](network.md) · [协议兼容](protocol-compatibility.md)

## 配置方式

Web 设置保存到数据库，对后续请求生效，重启后继续覆盖配置文件中的同名选项。自动领卡开关和时间在「领卡中心」修改。

直接运行程序时，可将 [config.example.json](../config.example.json) 复制为 `--root` 指定目录下的 `config.json` 后修改。Docker 默认只挂载数据目录；如需使用配置文件，须另行将它挂载到 `/app/config.json`。监听地址和端口修改后需要重启服务。

## 版本更新

### 网关程序

在「设置 → 版本更新」检查 `7sen1ot/zcode2api` 的最新正式 Release，仅提供更高版本的更新，同一发行版本不会覆盖本地热修复。

一键更新支持由 root 运行、以当前程序为主进程的 Linux/systemd 服务：沿用出站代理，校验发行包 SHA256，将旧程序、数据库快照及配置备份到 `data/updates/job-*` 后替换程序。账号和数据保留，启动失败时自动回滚。重启可能中断请求，完成后需重新登录。

Docker 在宿主机更新镜像并重建容器，其他部署方式使用发行包。Node.js、jsdom、Mihomo 等可选依赖需单独更新。

### ZCode 接口版本

默认每 5 天查询当前平台的 ZCode 官方稳定版清单，首次没有检查记录时立即查询，同步推理、额度与领卡 API 的版本标识。检查进度持久化，手动同步会重排下一次检查；查询失败保留原版本，不自动降级。关闭自动跟随后，可分别编辑管理和推理 API 版本。此设置独立于网关程序更新。

## 配置项

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `web_port` / `gateway_port` | `6789` / `6780` | 控制台与推理网关端口 |
| `host` | `127.0.0.1` | 本机直接运行时的监听地址 |
| `poll_interval_sec` | `5` | 账号余额轮询基础间隔，秒；限流和失败时延后检查 |
| `poll_jitter_sec` / `poll_concurrency` | `0` / `4` | 轮询抖动秒数与并发数 |
| `daily_claim_enabled` | `true` | 是否启用每日定时领取；可在领卡中心开关 |
| `daily_claim_time` | `19:02` | 每日自动领取免费卡的时间，北京时间 `HH:MM`；同一天已执行过则不重复领取 |
| `conversation_affinity_minutes` | `10` | 客户端提供会话标识时的账号亲和时间，分钟 |
| `default_reasoning_level` | `low` | 客户端与密钥均未指定时的默认思考强度，可选 `low` / `high` / `max` |
| `retry.rate_limit_retry_interval_ms` | `1000` | 上游未指定等待时间时，账号共享的并发暂忙冷却间隔；同时用于普通限流重试 |
| `retry.busy_wait_sec` | `60` | 本地账号槽位全部占用时，等待空闲账号的时长，秒 |
| `retry.max_attempts` / `retry.total_budget_ms` | `10` / `120000` | 普通故障的尝试次数 / 常规排队与重试预算（毫秒） |
| `http.first_token_timeout_ms` | `60000` | 上游首个有效内容超时，毫秒 |
| `http.idle_timeout_ms` | `120000` | 上游流空闲超时，毫秒 |
| `http.total_timeout_ms` | `0` | 整轮推理超时；`0` 表示不设整轮时限 |
| `zcode_version_auto_update` | `true` | 是否自动跟随 ZCode 官方稳定版 |
| `zcode_version_check_interval_sec` | `432000`（5 天） | 检查间隔，范围 60 至 31536000 秒；Web 支持分钟、小时、天，保存后重排计划 |
| `app_version` | `3.17.2` | 额度、领卡等管理 API 的版本标识 |
| `http.client_version` | `3.17.2` | 推理 API 的版本标识；首次升级迁移旧默认值 `0.17.0` |

## 额度与页面刷新

服务端按 `poll_interval_sec` 轮询额度，实际间隔还受账号数量、请求耗时、并发、抖动和错误退避影响。相关参数在「设置 → 额度轮询」修改；关闭网页不停止服务端轮询。

Web 概览和账号页在可见且没有进行交互时，约每 1 秒更新服务端已有数据。页面刷新与上游额度查询独立，不会因此每秒请求上游。

## 默认思考强度

可选 `low`、`high`、`max`，优先级为**客户端 → 密钥 → 全局设置**。

`low` 仍开启思考。客户端发送 `thinking.type=disabled` 时保留该设置；若模型返回 1210，请在客户端开启思考或移除关闭参数。

## 环境变量

| 环境变量 | 用途 |
| --- | --- |
| `ZCODE2API_DATA_DIR` | 指定数据目录 |
| `ZCODE2API_HOST` | 指定监听地址；Docker 镜像内默认为 `0.0.0.0` |
| `ZCODE2API_WEB_PORT` / `ZCODE2API_GATEWAY_PORT` | 指定控制台与网关端口 |

| `TZ` | 容器时区，Compose 默认 `Asia/Shanghai` |

## 调度与重试

单账号最多同时处理 3 个推理请求，所有模型共享名额；本地名额全部占用时，换号或按 `retry.busy_wait_sec` 排队。

| 情况 | 网关行为 |
| --- | --- |
| 明确的账号并发暂忙（3008/3009/3010） | 所有请求共享该账号的暂忙状态，优先换其他可用账号；优先遵守 `Retry-After`，缺失时默认冷却 1 秒 |
| 可用账号全部并发暂忙 | 进入统一队列，持续等待至恢复或取消；冷却结束后每账号仅放行一个恢复探测，开始有效输出后恢复正常名额 |
| 普通限流或过载（429、过载业务码、HTTP 503/529） | 先尝试其他账号，本次可用账号都受限后开启 **10 秒重试窗口**；不判定为代理节点故障 |
| 额度耗尽或凭据失效 | 从本次请求中排除该账号并换号，同时更新余额或授权状态 |
| 已经输出正文、思考或工具调用 | 停止整轮重放，避免重复回答或重复执行工具 |
| 参数错误 | 返回对应错误 |
| 明确的出口拦截或代理连接故障 | 全局代理池有可用备用节点且尚未输出时换节点重试；隔离时长和错误分类见[出口故障与切换](network.md#出口故障与切换) |
| 验证票据失效、需要人工验证或 SDK 环境错误 | 在原出口按[安全验证流程](network.md#安全验证)处理，返回具体验证错误，不据此剔除代理节点 |

上游并发暂忙不消耗普通重试次数和预算；普通限流窗口到期后返回错误。队列最多容纳 1024 个请求，按匹配账号与等待顺序调度，取消后立即移出。网络和普通服务端故障使用退避重试，正常生成中的回复不受重试预算截断。

## 日志保存与筛选

调用记录、调度时间线和审计写入数据目录的 SQLite 数据库，不按时间或条数自动清理，重启后保留。容器部署需保留挂载的数据目录。

各分区独立筛选、分页，每页 20 条，页面链接保留查询条件。调用记录支持状态、错误码、模型、账号和密钥筛选；调度支持结果、策略和候选账号搜索；审计支持操作者、动作和来源 IP。

默认开启「实时」，第一页约每 1 秒获取新记录；点击「实时」可暂停，「刷新」会重新查询最新记录。网页切到后台、编辑筛选、查看详情、选中文字或翻到历史页时暂停自动刷新。刷新失败保留当前内容，后续继续尝试。

报错内容为分类摘要和具体错误码，并非上游响应全文；可用接口记录中的 `request_id`、`trace_id` 关联排查。

## 领卡行为

领卡中心只识别上游活动投放中的 `ZCODE GLOBAL BUILD`、`ZCODE WEEKEND BUILD` 免费卡，使用当次返回的 `plan_id` 领取；卡片开放时间、额度和有效期以上游为准。

每日定时领取默认开启，时间为北京时间 19:02（固定使用 `Asia/Shanghai` 时区）。可在「领卡中心」开关自动领取、修改每日执行时间；保存后重排下一次执行，无需重启。对应配置为 `daily_claim_enabled` 和 `daily_claim_time`，旧的 `claim_auto_enabled`、`claim_auto_min` 不再生效。

定时任务只需服务持续运行。同一北京时间日期只记录执行一次，重启或改时间不会重放已执行的任务；停机错过时间后等待下一个计划时间，不补跑。需人工验证的结果保留，进入领卡中心手动处理。

手动、批量和定时领取的 SDK 流程、浏览器兜底及中断处理，统一见[领卡验证](network.md#领卡验证)。

网页 Cookie 导入仅用于受支持的平台资料等接口，**不能用于推理或余额查询**。推理和领卡需要账号具备有效的 ZCode 凭据。

## 数据目录

管理密码、数据库与端口文件默认位于 `data/`。Windows 启停脚本中的相对 `ZCODE2API_DATA_DIR` 以项目或解压目录为基准。备份范围和凭据保护要求见[安全说明](../SECURITY.md#账号与数据)。
